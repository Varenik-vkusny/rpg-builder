# RPG Builder — описание проекта

> Снимок на 28.09.2026, не обновляется — источник правды VISION.md.

**Курсовая работа. Мобильное приложение на Flutter для разработчиков RPG-игр.**
Срок сдачи — до 20 февраля 2027 года.

## 1. Суть проекта

RPG Builder — инструмент для проектирования игрового контента. Автор описывает мир своей игры
(локации, предметы, персонажей, квесты), а ИИ-ассистент помогает наполнять и менять этот мир
обычной фразой, например: «Третья штольня затоплена, слизни там жить не могут».

Главная задача продукта: **связанный мир игры безопасно меняется одной фразой — связи не ломаются,
все изменения видны до записи и откатываются.**

## 2. Проблема

В RPG-игре объекты связаны друг с другом: квест требует убить врага, враг роняет ключ, ключ нужен
для другого квеста. Задумка игры постоянно меняется, и при каждой правке связанный контент
расходится: автор ищет связи вручную, что-то забывает, и ошибки находят уже игроки.

Обычные ИИ-чаты (ChatGPT и подобные) могут придумать новый предмет или персонажа, но не умеют
безопасно изменить **существующий** мир, в котором объекты ссылаются друг на друга.

## 3. Пользователи

| Роль | Описание |
|---|---|
| Основной пользователь | Инди-разработчик-одиночка, который месяцами делает свою RPG и регулярно меняет задумку |
| Второй пользователь | Участник геймджема, которому нужно быстро наполнить пустой мир |
| Не пользователь | Игрок |

Сценарий использования: автор работает с телефона короткими сессиями — пришла идея, написал
одну фразу, посмотрел план изменений, применил. Раз в неделю проверяет мир на ошибки.
За компьютером выгружает мир в игровой движок.

## 4. Как это работает

Ассистент не записывает в базу ни одной строки. Он только предлагает **план изменений**,
который проходит шесть шагов:

1. **Область.** Автор выбирает объект (локацию, квест или персонажа). Ассистенту доступен только он
   и связанные с ним объекты.
2. **План.** ИИ-модель читает объекты области и возвращает список операций: создать, изменить, удалить.
3. **Границы.** Сервер и приложение отклоняют операции над объектами вне области (проверка в двух местах).
4. **Проверка на копии.** План применяется к копии мира в памяти телефона, и запускаются правила проверки.
   Если есть ошибки, ассистент исправляет план сам — не больше двух раз.
5. **«Было → стало».** Автор видит каждое изменённое поле до записи и решает: «Применить» или «Отклонить».
6. **Запись и откат.** План записывается в базу одной транзакцией (всё или ничего) и сохраняется
   в истории. Любой набор изменений можно откатить.

Если просьба противоречит правилам мира, ассистент не исправляет её молча, а задаёт автору вопрос
с вариантами ответа.

## 5. Возможности

| Раздел | Что умеет |
|---|---|
| Вход и миры | Регистрация и вход; автор видит только свои миры; создание мира (название, сеттинг, тон, уровни); обзор мира |
| Содержимое | Создание, просмотр, правка и удаление локаций, предметов, персонажей и квестов; добыча врагов с шансами; шаги и награды квестов; фильтры |
| Проверка мира | Ошибки: битые ссылки, удаление объекта, на который есть ссылки, квест без шагов или без выдающего. Предупреждения: предмет нельзя получить, урон выше допустимого для уровня, цена не растёт с редкостью, повтор названий |
| Ассистент | Просьба фразой, план «было → стало», автоисправление, вопрос автору, применение, история и откат |
| Выход в игру | Экспорт мира в JSON для Unity (также читают Godot и Flame), отправка через «Поделиться»; импорт образцов из открытой базы Open5e с указанием источника |

## 6. Ключевые правила (гарантии)

1. ИИ не пишет в базу — у модели только инструменты чтения и «предложить план».
2. Без подтверждения человеком ничего не записывается.
3. План записывается целиком или не записывается вовсе (одна транзакция).
4. Мир с ошибкой проверки не сохраняется — ошибка блокирует «Применить».
5. Операция вне выбранной области отклоняется всегда.
6. Любой применённый набор изменений можно откатить.
7. Проверку мира выполняет код (Dart), а не ИИ: одни и те же правила на экране проверки и на копии перед применением.
8. Ключ доступа к ИИ хранится только на сервере и не попадает в приложение.

## 7. Технологии

| Слой | Технология |
|---|---|
| Приложение | Flutter, Dart (Android) |
| База данных | PostgreSQL в Supabase: 11 таблиц, связи многие-ко-многим, журнал изменений, построчная защита данных (RLS) |
| Запись плана | Функция PostgreSQL `apply_change_set` — все операции в одной транзакции |
| Вызов ИИ | Серверная функция Supabase (Edge Function, TypeScript); бесплатная модель через Groq, провайдер меняется настройкой |
| Проверка мира | Правила на Dart в приложении |
| Образцы | Open5e API (лицензия CC BY 4.0) |
| Экспорт | JSON под `JsonUtility` Unity, системное окно «Поделиться» |

## 8. Аналоги

| Продукт | Что делает | Отличие RPG Builder |
|---|---|---|
| articy:draft | Диалоги, персонажи, логика, экспорт в Unity и Unreal | Настольная программа и ручная работа; у нас телефон и ассистент с проверяемым планом |
| Arcweave | Облачный редактор сюжета | Упор на ветвление сюжета, а не на объекты с характеристиками и баланс |
| World Anvil, Kanka, Campfire | Вики мира для писателей и мастеров | Статьи и лор без проверки баланса и экспорта в движок |

## 9. Чего проект не делает

Офлайн-режим, генерацию картинок, автоматическое применение изменений без человека, совместную
работу над миром, диалоги NPC и ветвление сюжета, плагин внутри Unity, веб- и ПК-версию.

## 11. Демонстрационный сценарий

На примере мира «Пепельные копи» (горняцкий город под вулканом): автор пишет
«Третья штольня затоплена, слизни там жить не могут» → ассистент предлагает связанные изменения
(локация, враги, шаг квеста, добыча) → проверка ловит слишком сильного врага → автор видит «было → стало»
и применяет план → затем откатывает его, и мир возвращается в прежнее состояние → мир выгружается в JSON.
