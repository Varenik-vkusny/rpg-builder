# Курсовая: кузница игрового контента

Мобильное приложение на Flutter для разработчика RPG. Ты описываешь мир, а ИИ-ассистент наполняет его и меняет по одной фразе: «третья штольня теперь затоплена». Код гарантирует, что мир не сломается: ИИ только предлагает план, приложение проверяет его на копии, ты подтверждаешь, любое изменение откатывается.

| | |
|---|---|
| Пользователь | Разработчик игры: инди-одиночка, студент, участник геймджема. Не игрок |
| Боль | Мир живой: задумка меняется, а связанный контент при каждой правке расходится и ломается |
| Результат | Мир, который безопасно меняется одной фразой, и JSON-файл для Unity, Godot или Flame |
| Срок | До 20 февраля 2027 |

**Главный вопрос на защите — «чем это лучше ChatGPT».** Чат придумает предмет, но не поменяет существующий мир, где квест ссылается на врага, враг роняет ключ, а ключ нужен другому квесту. Кузница меняет связанные объекты вместе, показывает каждое изменение до сохранения и не даёт записать сломанный мир.

Ядро курсовой — **ассистент правок**: область → план → проверка на копии → подтверждение → транзакция → откат. Генерация новых объектов — частный случай: план из одних операций «создать». Формы, списки и экспорт — обвязка вокруг ядра.

## 1. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Ядро ИИ | Ассистент правок с планом изменений | Прошлый раз комиссии было непонятно, что показывать; безопасная правка связанного мира — то, чего не умеет чат |
| Направление | Инструмент для проектирования игрового контента | Связано с будущей игрой для диплома, но работает без неё |
| Жанр | RPG-подобные игры | Понятные сущности, богатая база, совпадает с открытыми данными Open5e |
| Роль телефона | Камера (скетч) и голос | Без них это урезанная десктопная программа |
| Кто проверяет мир | Код на Dart, не ИИ | Детерминированно, бесплатно, без интернета |
| Unity в курсовой | Не обязателен | Экспорт — демонстрация интеграции; сцена в Unity — бонус |
| Источник образцов | Open5e (CC BY 4.0) | Fandom запрещает автоматическое скачивание |
| Имя приложения в теме | Не ставим | QuestSmith, LoreSmith, LoreForge заняты |

## 2. Ассистент правок — ядро

Ассистент не пишет в базу ни одной строки. Он составляет **план изменений**, и план проходит шесть шагов, каждый — код, а не обещание.

1. **Область.** Выбираешь объект: локацию, квест или персонажа. Ассистенту видно только его и связанное с ним на расстоянии до двух связей.
2. **План.** Модель читает объекты области через инструменты и возвращает список операций: создать, изменить, удалить. Инструмента записи у неё нет.
3. **Границы.** Серверная функция и приложение отклоняют операции над объектами вне области. Проверка в двух местах: одна ошибётся — поймает вторая.
4. **Проверка на копии.** План применяется к копии мира в памяти телефона, прогоняются все правила. Есть ошибки — ассистент получает их списком и исправляет план сам, не больше двух раз.
5. **Было → стало.** Экран показывает каждое изменённое поле, созданные и удалённые объекты, оставшиеся предупреждения. Применяешь целиком или отклоняешь.
6. **Транзакция и откат.** План записывается одной транзакцией в Postgres: либо всё, либо ничего. Набор изменений сохраняется с «было» и «стало» и откатывается.

### Пример: «Третья штольня теперь затоплена, слизни там жить не могут»

| Операция | Объект | Было → стало |
|---|---|---|
| изменить | Локация «Штольня №3» | описание: обвалившаяся выработка → затоплена по пояс, крепь гниёт |
| изменить | Враг «Пепельный слизень» | локация: Штольня №3 → Штольня №1 |
| создать | Враг «Утопленник-крепильщик» | 3 уровень, здоровье 30, урон 14, локация Штольня №3 |
| изменить | Квест «Обвал в третьей штольне», шаг 2 | убить 4 слизня → убить 3 утопленников |
| создать | Добыча | утопленник → ключ от лебёдки, 35% |
| удалить | Добыча | слизень → ключ от лебёдки, 35% |

| Попытка | Проверка на копии |
|---|---|
| 1 | Внимание: урон утопленника 14 выше потолка для 3 уровня (8). Список ушёл ассистенту |
| 2 | Чисто: урон снижен до 8, добавлено пояснение «медленный, но живучий». Все связи целы |

Шесть связанных изменений по одной фразе, ошибка ИИ поймана кодом до подтверждения. **Это главная сцена защиты.**

### Гарантии

| Гарантия | Чем обеспечена |
|---|---|
| ИИ не пишет в базу | У модели только инструменты чтения и «предложить план» |
| Не трогает лишнее | Операции вне области отклоняются в функции и в приложении |
| Не ломает связи | План применяется к копии, правила те же, что на экране «Проверка мира» |
| Не удалит нужное | Удаление объекта со ссылками — ошибка, если план их не исправляет |
| Не зациклится | Не больше двух исправлений, дальше «Применить» недоступно |
| Всё или ничего | Одна транзакция в Postgres |
| Можно передумать | Откат создаёт обратный набор операций |

### Чего ассистент не делает

| Делаем | Не делаем |
|---|---|
| Правки в выбранной области | «Перепиши весь мир» без области |
| Текст и числа объектов | Картинки |
| Подтверждение человеком перед записью | Автоприменение |
| Откат наборов по одному | Историю с ветками, как в git |

## 3. Сценарий: от идеи до игры

Пример мира — **«Пепельные копи»**: горняцкий город под спящим вулканом, тёмное фэнтези, уровни 1–10.

1. **Создаёт мир.** Название, сеттинг в 2–3 предложения, тон, диапазон уровней.
2. **Наполняет.** «Создай 10 предметов для уровней 1–5, в основном обычные» → план из десяти операций «создать».
3. **Добавляет со скетча.** Фотографирует рисунок бригадира, ИИ делает карточку персонажа.
4. **Надиктовывает квест.** «Бригадир просит разобраться с обвалом, там слизни, нужен ключ от лебёдки».
5. **Проверка мира** находит: «Ключ от лебёдки нельзя получить».
6. **Просит исправить.** «Пусть ключ выпадает со слизней» → план из одной операции.
7. **Меняет задумку.** «Третья штольня затоплена» → шесть связанных изменений, автоисправление баланса.
8. **Применяет, потом откатывает.**
9. **Экспортирует** мир в `ashen_mines.json` и отправляет себе в Telegram.
10. **Загружает в Unity** — десяток строк на C#.

## 4. Объекты мира

У каждого объекта есть `slug` — короткий постоянный идентификатор (`foreman_pick`). Через него объекты ссылаются друг на друга в базе, в плане и в экспорте.

Редкость: обычный · необычный · редкий · эпический · легендарный.

| Объект | Поля |
|---|---|
| **Предмет** | тип (оружие/броня/расходник/квестовый/прочее), редкость, уровень, урон или защита, цена, описание, происхождение (вручную / ассистент / скетч / Open5e) |
| **Персонаж** | роль (NPC/враг/босс), уровень, здоровье, атака, локация, история, скетч, добыча с шансами (у врагов) |
| **Квест** | кто выдаёт (NPC), шаги по порядку (поговорить / убить N / собрать N / прийти), награды |
| **Локация** | описание, диапазон уровней, кто внутри, какие квесты ведут сюда |
| **Мир** | сеттинг, тон, диапазон уровней — контекст для каждой просьбы ассистенту |

## 5. База данных

Postgres в Supabase: 11 своих таблиц плюс встроенные пользователи. Ценное для курсовой: связи многие-ко-многим, журнал изменений с «было» и «стало», применение плана одной транзакцией.

| Таблица | Ключевые поля | Связи и ограничения |
|---|---|---|
| `projects` | id, owner_id, title, setting, tone, level_min, level_max | owner_id → пользователь Supabase; level_min ≤ level_max |
| `locations` | id, project_id, slug, name, description, level_min, level_max | (project_id, slug) уникальны |
| `characters` | id, project_id, slug, name, role, level, hp, attack, location_id, story, sketch_path, source | role ∈ npc/enemy/boss; location_id → locations |
| `items` | id, project_id, slug, name, type, rarity, level, damage, defense, price, description, source, source_ref | source_ref хранит атрибуцию Open5e |
| `quests` | id, project_id, slug, title, giver_id, level, description | giver_id → characters (роль npc) |
| `quest_steps` | id, quest_id, position, kind, target_*_id, amount | (quest_id, position) уникальны; ровно одна цель по kind |
| `quest_rewards` | quest_id, item_id, amount | составной ключ, многие-ко-многим |
| `loot_entries` | character_id, item_id, chance | составной ключ, 0 < chance ≤ 100 |
| `change_sets` | id, project_id, scope_type, scope_slug, request, summary, status, created_at, reverts_id | status ∈ applied/rejected/reverted |
| `change_ops` | id, change_set_id, position, action, object_type, object_slug, before, after | action ∈ create/update/delete; before и after — JSON |
| `generations` | id, project_id, change_set_id, input_tokens, output_tokens, attempts, created_at | журнал запросов к ИИ, учёт стоимости |

Связи содержимого: всё принадлежит `projects`. `loot_entries` соединяет персонажей с предметами, `quest_rewards` — квесты с предметами, `quest_steps` принадлежит квесту.

План применяется функцией базы `apply_change_set`: Postgres выполняет все операции в одной транзакции. Не прошла хотя бы одна — не записывается ничего.

Результаты проверки мира в базе не хранятся: правила пересчитываются за доли секунды, сохранённый отчёт устаревал бы после любой правки.

## 6. Проверка мира

Проверку делает **код на Dart**. Одни и те же правила работают на экране «Проверка мира» и на копии мира перед применением плана.

| Уровень | Правило | Пример |
|---|---|---|
| Ошибка | Ссылка на несуществующий объект | Шаг квеста требует `winch_key`, а такого предмета нет |
| Ошибка | Удалён объект, на который есть ссылки | План удаляет врага, а квест просит его убить |
| Ошибка | Операция вне области | При правке штольни план меняет предмет из другого города |
| Ошибка | Квест без шагов или без выдающего | Квест не привязан ни к одному NPC |
| Внимание | Предмет нельзя получить | Ключ не выпадает и не выдаётся наградой |
| Внимание | Урон выше потолка уровня | Враг 3 уровня с уроном 14 при потолке 8 |
| Внимание | Цена не растёт с редкостью | Эпический предмет дешевле медианы редких |
| Внимание | Враг сильнее своей локации | Босс 8 уровня в штольне для уровней 2–4 |
| Внимание | Повтор названий | Два предмета «Пепельная настойка» |

Ошибка блокирует «Применить». Предупреждение можно проигнорировать — решает автор мира.

Формула потолка урона (настраивается автором):

```
потолок = 4 + уровень × 2 × множитель редкости
множитель: обычный 1.0 · необычный 1.2 · редкий 1.5 · эпический 1.9 · легендарный 2.4
пример: обычный объект 2 уровня → 4 + 2 × 2 × 1.0 = 8
```

## 7. ИИ под капотом

Путь данных: телефон → серверная функция → модель → план → проверка на копии на телефоне → подтверждение → транзакция в базе → экспорт в движок.

Ключ API зашитый в приложение достали бы из APK за минуты, поэтому к модели ходит только серверная функция Supabase.

### Инструменты модели

| Инструмент | Что делает | Пишет в базу |
|---|---|---|
| `find_in_scope` | Ищет объекты области по названию и типу | нет |
| `read_object` | Возвращает поля объекта и его связи | нет |
| `find_samples` | Даёт 2–3 образца из Open5e для баланса | нет |
| `propose_plan` | Принимает итоговый план: описание и список операций | нет, план возвращается на телефон |

Инструменты объявлены со строгой схемой (`strict: true`), поэтому план всегда соответствует JSON-схеме.

### Формат плана

```json
{
  "summary": "Штольня №3 затоплена: слизни переселены, появились утопленники",
  "ops": [
    { "action": "update", "type": "location", "slug": "shaft_three",
      "set": { "description": "Затоплена по пояс, крепь гниёт" } },
    { "action": "update", "type": "character", "slug": "ash_slime",
      "set": { "location": "shaft_one" } },
    { "action": "create", "type": "character", "slug": "drowned_timberman",
      "fields": { "name": "Утопленник-крепильщик", "role": "enemy", "level": 3,
                  "hp": 30, "attack": 8, "location": "shaft_three" } },
    { "action": "update", "type": "quest_step", "quest": "shaft_three_collapse",
      "position": 2, "set": { "target": "drowned_timberman", "amount": 3 } },
    { "action": "create", "type": "loot", "character": "drowned_timberman",
      "item": "winch_key", "fields": { "chance": 35 } },
    { "action": "delete", "type": "loot", "character": "ash_slime", "item": "winch_key" }
  ]
}
```

### Что делает ИИ, а что код

| ИИ | Код |
|---|---|
| Понимает просьбу на обычном языке | Ограничивает область |
| Решает, какие объекты затронуть | Отклоняет операции вне области |
| Придумывает названия, описания, числа | Проверяет связи и баланс на копии |
| Исправляет план по списку ошибок | Ограничивает число исправлений, пишет транзакцией, хранит историю |

## 8. Экспорт в движок

Один файл на мир. Формат подогнан под встроенный `JsonUtility` в Unity: корень — объект, внутри только массивы и простые поля, ссылки через slug. Словари `JsonUtility` не читает, поэтому их в формате нет.

```json
{
  "schemaVersion": 1,
  "world": { "slug": "ashen_mines", "title": "Пепельные копи", "levelMin": 1, "levelMax": 10 },
  "items": [
    { "slug": "foreman_pick", "name": "Кирка десятника", "type": "weapon",
      "rarity": "uncommon", "level": 3, "damage": 9, "price": 120 }
  ],
  "characters": [
    { "slug": "drowned_timberman", "name": "Утопленник-крепильщик", "role": "enemy",
      "level": 3, "hp": 30, "attack": 8, "location": "shaft_three",
      "loot": [ { "item": "winch_key", "chance": 35 } ] }
  ],
  "quests": [
    { "slug": "shaft_three_collapse", "title": "Обвал в третьей штольне",
      "giver": "foreman_erden",
      "steps": [
        { "kind": "talk",    "target": "foreman_erden",     "amount": 1 },
        { "kind": "kill",    "target": "drowned_timberman", "amount": 3 },
        { "kind": "collect", "target": "winch_key",         "amount": 1 }
      ],
      "rewards": [ { "item": "foreman_pick", "amount": 1 } ] }
  ]
}
```

Загрузка в Unity:

```csharp
[System.Serializable] public class Item { public string slug, name, type, rarity; public int level, damage, price; }
[System.Serializable] public class ContentPack { public int schemaVersion; public Item[] items; }

var json = Resources.Load<TextAsset>("ashen_mines").text;
var pack = JsonUtility.FromJson<ContentPack>(json);
Debug.Log(pack.items[0].name); // Кирка десятника
```

Поля, которых нет в классе C#, `JsonUtility` пропускает. Тот же файл без изменений читают Godot и Flame.

Файл уходит через системное окно «Поделиться»: Telegram, почта, Google Диск. Перед отправкой приложение ещё раз запускает проверку.

| Сервер и база | supabase_flutter: Postgres, вход, хранилище | База, пользователи и фото без своего сервера |
| Транзакция плана | функция Postgres `apply_change_set` | Все операции вместе или никак |
| Вызов ИИ | Supabase Edge Function на TypeScript, `npm:@anthropic-ai/sdk` | Прячет ключ API, проверяет область; SDK Claude для Dart нет |
| Модель | Claude Opus 5 (`claude-opus-5`), инструменты со строгой схемой | Надёжно следует схеме, понимает изображения |
| Камера | image_picker | Скетч |
| Голос | speech_to_text | Распознавание средствами телефона |
| Образцы | http + api.open5e.com/v2 | `/magic-items/`, `/creatures/`, `/equipment/` |
| Отправка файла | share_plus | Системное «Поделиться» |

Версии пакетов фиксируем в момент создания проекта, а не заранее.

## 17. Вопросы комиссии

**Чем это лучше ChatGPT?** Чат придумывает текст, но не меняет существующий связанный мир. Здесь ассистент меняет связанные объекты вместе, код проверяет результат на копии, запись идёт одной транзакцией после подтверждения.

**Что если ИИ удалит нужное?** У модели нет инструмента записи. Удаление объекта со ссылками — ошибка проверки, такой план нельзя применить. Применённое откатывается.

**Что делает ИИ, а что код?** ИИ понимает просьбу и предлагает операции. Код ограничивает область, проверяет связи и баланс, ограничивает исправления, пишет транзакцией, хранит историю.

**Зачем это на телефоне?** Идеи приходят не за компьютером: скетч фотографируется, правка надиктовывается, план применяется в дороге.

**Где ключ API?** Только в серверной функции Supabase, в APK его нет.

**Откуда образцы?** Open5e, SRD 5.1 под CC BY 4.0, источник сохраняется у каждого импортированного объекта.

**Что без интернета?** В курсовой приложение требует сеть. Офлайн — в развитие проекта.
