## 1. Что это и для кого

Мобильное приложение на Flutter для разработчика RPG. Автор описывает мир, а ИИ-ассистент
наполняет его и меняет по одной фразе: «третья штольня теперь затоплена». Код гарантирует,
что мир не сломается.

| | |
|---|---|
| Главный пользователь | **Инди-разработчик-одиночка**, который месяцами делает свою RPG и каждую неделю правит задумку |
| Второй пользователь | Участник геймджема: быстро наполняет пустой мир. Получает генерацию как частный случай плана |
| При споре нужд | Побеждает инди-одиночка |
| Не пользователь | Игрок |
| Контекст | Курсовая, защита до 20 февраля 2027 |

## 2. Главная задача продукта

**Связанный мир игры безопасно меняется одной фразой: связи не ломаются, всё видно до записи и откатывается.**

Боль: задумка живёт и меняется, а связанный контент (квест → враг → ключ → другой квест)
при каждой правке расходится. Автор ищет связи руками, что-то забывает, дыры находят игроки.

## 3. Кто пользуется

| Роль | Что может |
|---|---|
| Автор мира | Всё в своих мирах. Чужие миры не видит |

Одна роль. Совместной работы нет.

### Один день автора

| Когда | Что делает |
|---|---|
| В дороге, вечером | Пришла идея → фраза, голос или фото скетча → план → применил |
| Раз в неделю | Проверка мира → список проблем → «попросить ассистента исправить» |
| У ПК | Экспорт → JSON → в Unity, Godot или Flame |

## 4. Зоны продукта

Граница задачи называется зоной: «трогай только зону Проверка». Задача на две зоны — слишком большая.

| Зона | Что внутри | Пример границы |
|---|---|---|
| **Вход и миры** | Знакомство, вход, регистрация, список миров, новый мир, обзор мира, профиль | «добавь счётчик проблем в список миров — зона Вход и миры» |
| **Содержимое** | Места (с вложенностью), события, предметы, персонажи, квесты: списки, фильтры, страницы, редакторы | «фильтр по редкости у предметов — зона Содержимое» |
| **Проверка** | Правила мира на Dart, экран «Проверка мира», скрытые предупреждения | «новое правило про цену — зона Проверка» |
| **Ассистент** | Область, план, «было → стало», проверка на копии, применение, история, откат, правка с 💬, скетч, голос, быстрый заказ | «автоисправление плана — зона Ассистент» |
| **Карта** | Холст мест: перемещение и масштаб, блоки мест, вход уровнем ниже, ⚡ событий, фото карты фоном | «перетаскивание блока — зона Карта» |
| **Выход в игру** | Экспорт JSON, «Поделиться», библиотека Open5e | «превью JSON перед отправкой — зона Выход в игру» |

## 5. Главный сценарий

```
просьба (текст / голос / скетч) + область
  → ИИ читает область и предлагает план (создать / изменить / удалить)
  → код отклоняет операции вне области
  → план применяется к копии мира, прогоняются правила
  → ошибки? ИИ исправляет план сам, не больше 2 раз
  → экран «было → стало»
  → автор: Применить / Отклонить
  → одна транзакция в базе, набор изменений в историю
  → при желании: Откатить
```

Генерация новых объектов — тот же путь, план из одних операций «создать».

Сцена защиты: «Третья штольня затоплена, слизни там жить не могут» → 6 связанных изменений →
проверка ловит урон 14 при потолке 8 → ИИ исправляет на 8 → Применить → Откатить.

## 6. Что продукт умеет

**Вход и миры**
- Автор регистрируется, входит и видит только свои миры
- Автор создаёт мир: название, сеттинг, тон, диапазон уровней
- Автор видит обзор мира: сколько объектов, сколько проблем, последние изменения

**Содержимое**
- Автор создаёт, смотрит, меняет и удаляет локации, предметы, персонажей, квесты вручную
- Автор задаёт врагу добычу с шансами, квесту — шаги по порядку и награды
- Автор фильтрует предметы по редкости и типу, персонажей — по роли
- Автор кладёт место внутрь другого: Копи › Штольня №3 › Забой (не глубже 3 уровней)
- Автор создаёт событие — сцену в месте: враги с числом, предметы; квест может требовать «пройти событие»

**Проверка**
- Автор видит все ошибки и предупреждения мира одним списком
- Ошибки: битая ссылка, удалён объект со ссылками, операция вне области, квест без шагов или выдающего
- Предупреждения: предмет нельзя получить, урон выше потолка уровня, цена не растёт с редкостью, враг сильнее локации, повтор названий
- Автор просит ассистента исправить проблему прямо со списка
- Вложенность: место в самом себе, глубже 3 уровней, удаление места с вложенными — ошибки; уровни вне родителя — предупреждение
- События: событие без места и битые ссылки — ошибки; враг сильнее своего места — предупреждение; предмет из события считается получаемым
- Автор скрывает предупреждение — оно уходит во вкладку «Скрытые» и всплывает снова, если причина изменилась. Ошибки не скрываются

**Ассистент**
- Автор выбирает область (место, квест, персонаж) и пишет просьбу обычной фразой. Место в области тянет за собой вложенные места на 1 уровень вниз, их события и жителей
- Автор нажимает ✏ на странице объекта, оставляет 💬 у полей разных объектов, отправляет пачкой — ассистент строит один план. Комментарий — указка «вот про это», не лимит. Упомянул объект вне области — ассистент спрашивает, расширить ли
- Автор видит план «было → стало» по каждому полю и результат проверки до записи
- Ассистент сам исправляет план по ошибкам, не больше двух раз
- Автор применяет план целиком или отклоняет
- Автор видит историю наборов изменений и откатывает любой
- Автор фотографирует скетч, ассистент предлагает карточку персонажа *(обязательно)*
- Автор надиктовывает просьбу голосом *(если успеваем)*
- Автор заказывает пачку объектов: тип, количество, уровни, редкость *(если успеваем)*

**Карта** — выглядит и ведёт себя как карта (как холст Figma), в стиле приложения
- Автор двигает и масштабирует холст пальцами; места — блоки, которые хочется нажать: цвет места, жители, ⚡ события, значок проблемы
- Автор перетаскивает блоки; новое место (в том числе от ассистента) встаёт само в свободное место
- Автор «входит» в место — открывается холст уровнем ниже; путь «Копи › Штольня №3» сверху, назад — на уровень вверх
- Автор кладёт фото или скетч карты фоном холста *(последняя ступень, если успеваем)*

**Выход в игру**
- Автор экспортирует мир в JSON под `JsonUtility` Unity и отправляет через «Поделиться»
- Перед экспортом мир проверяется ещё раз
- Автор ищет образцы в Open5e и импортирует их с атрибуцией

## 7. Чего продукт НЕ делает

| Не делаем | Почему |
|---|---|
| Офлайн-режим | Удваивает сложность базы, не влезает в курсовую |
| Картинки от ИИ | Ядро — связи и числа, не арт |
| Автоприменение плана | Человек подтверждает всегда |
| Историю с ветками, как в git | Хватает линейной истории с откатом по одному |
| «Перепиши весь мир» без области | Область — основа безопасности и цены |
| Совместную работу над миром | Одна роль; это в диплом |
| Диалоги NPC, ветвление сюжета | Поле articy и Arcweave, второй продукт |
| Плагин внутри Unity | Только JSON-файл, загрузка — десяток строк C# |
| Оплату и подписки | Курсовая, не бизнес |
| Push-уведомления | Нечего сообщать без действия автора |
| Веб- и ПК-версию | Отложено, не в курсовую |
| Условия запуска событий (шаг квеста, шанс, «один раз») | Это игровая логика — дело игры; событие у нас сцена |
| Вложенность мест глубже 3 уровней | Не читается на телефоне, путает модель |
| Переходы между местами | Заменены вложенностью (решение 29.09.2026) |

## 8. Правила, которые нельзя нарушать

1. **ИИ не пишет в базу.** У модели только инструменты чтения и «предложить план».
2. **Без подтверждения человеком ничего не записывается.**
3. **План записывается целиком или не записывается вовсе** — одна транзакция.
4. **Мир с ошибкой проверки не сохраняется.** Ошибка блокирует «Применить».
5. **Операция вне области отклоняется всегда** — и на сервере, и в приложении.
6. **Любой применённый набор изменений можно откатить.**
7. **Проверка одна:** те же правила на экране «Проверка мира» и на копии перед применением.
8. **`slug` объекта не меняется после создания** — на нём держатся ссылки и экспорт.
9. **Ключ API никогда не попадает в приложение** — только серверная функция.
10. **Область расширяет только автор** — своим ответом на вопрос ассистента, не модель.

## 9. Как выглядит «продукт готов»

Автор проходит весь сценарий вживую, ни разу не открыв блокнот, таблицу или консоль базы:

1. Регистрируется, создаёт мир «Пепельные копи»
2. Наполняет его примерно до 40 объектов: вручную и через ассистента
3. Фотографирует скетч бригадира — получает карточку персонажа
4. Проверка мира находит «ключ от лебёдки нельзя получить», ассистент исправляет
5. «Третья штольня затоплена» → 6 изменений, автоисправление баланса → Применить
6. Откатывает этот набор
7. Экспортирует `ashen_mines.json` и отправляет себе в Telegram

**Провал:** если к 31 декабря 2026 сцена «штольня» (фраза → план → проверка → применить)
не проходит вживую — объём режется: карта, Open5e и скетч уходят, ядро доделывается.

## 10. Решения и почему

| Решение | Почему — не отменять, не зная этого |
|---|---|
| Ядро — ассистент правок, а не генератор | Правка связанного мира — то, чего не умеет ChatGPT. Это ответ на главный вопрос защиты |
| Главный пользователь — инди-одиночка | Его боль (правка ломает связи) и есть ядро; джемеру хватает генерации как частного случая |
| Проверку делает код на Dart, не ИИ | Детерминированно, бесплатно, без сети; ИИ ошибается — код ловит |
| Проверка на копии в памяти телефона | Те же правила, что на экране; ошибки видны до записи |
| Не больше 2 автоисправлений | Защита от зацикливания и расходов на API |
| Ключ API только в серверной функции Supabase | Из APK ключ достают за минуты |
| Модель — бесплатная (Groq и др.), провайдер меняется настройкой (владелец, 26.09.2026) | Платить за API владелец не хочет. Слабая модель путается в сложном плане — поэтому план упрощается под неё, а сервер сам чинит опечатки и повторяет. Код ловит ошибку ИИ, чья модель — вторично |
| ИИ спрашивает автора, а не правит просьбу молча (владелец, 25.09.2026) | Просьба спорит с правилами → окно с вариантами, первый «советую». Решение остаётся за человеком |
| Скетч обязателен, голос — нет | Без камеры нет ответа на «зачем это на телефоне»; голос дешёвый, но не критичный |
| Карта после ядра | При нехватке времени страдает карта, а не сцена защиты |
| Карта — холст, а не сетка (владелец, 29.09.2026) | «Карта должна выглядеть как карта, как в Figma, каждый блок вкусный для нажатия, в нашем стиле». Положение блока на холсте — раскладка автора: не входит в план ИИ, историю и откат, в экспорт идёт только родитель |
| Сначала вложенность, потом события | События лежат в местах; вложенность дешевле и нужна карте первой |
| Событие — сцена без условий (29.09.2026) | Условия запуска — игровая логика и вдвое дороже; модель под них путалась бы, как со старым планом |
| 💬 — указка, не лимит (29.09.2026) | Автор не держит в голове и не переключается в чат; лимит объектов не ставим. Правило 10 сохраняет безопасность |
| Скрытое предупреждение всплывает при изменении причины | Скрыть навсегда = пропустить новую проблему |
| Стиль «Телетекст на графите» (28.09.2026) | Голубой — только главные действия, пурпурный — только «изменено». Цвет со смыслом не тратится на украшение |
| Open5e, а не Fandom | CC BY 4.0; Fandom запрещает автоматическое скачивание |
| Экспорт под `JsonUtility` (без словарей) | Встроенный парсер Unity; тот же файл читают Godot и Flame |
| Supabase (Postgres) | Транзакция плана, пользователи, хранилище фото без своего сервера. ⚠️ Уточнить у преподавателя: можно ли облачную базу |
